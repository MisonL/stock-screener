# 策略：跌深横盘突破

本文只写**最终生效的规则**——参数取值、判据来源、为什么这么定。开发过程中的多次试错与数据修正不在此列，最终值以 `config/strategy.yaml` 为准。

---

## 1. 要抓的形态

三段式：

```
        前期下跌              横盘（跌不动了）         突破（买点）
   ┌──────────────┐      ┌─────────────────┐      ┌──►
   │  从高点回撤   │      │ 窄幅震荡、量能枯竭 │      │ 放量站上箱体上沿
   │  均线空头排列 │      │ 波动率收敛、均线粘合│      │
   └──────────────┘      └─────────────────┘      └──►
```

核心洞察：**「横盘」本身不是信号，「横盘 + 缩量 + 位置低」才是**。价格窄幅只是表象，成交萎缩才是「跌不动」的证据。A 股里「横盘 + 放量」与「横盘 + 缩量」含义完全相反——前者可能是出货，后者才可能是筑底。所以量能因子是硬条件，不是加分项。

设计原则：**不做布尔筛选，而是打分排序取 Top N**，且**每只票必须能说清为什么被选中**（分项因子值随推送一起发出），让用户自己判断是否认同，而不是只能信或不信。

---

## 2. 因子定义

全部参数在 `config/strategy.yaml` 中。

> **注意：阈值按市场分组**：下表列的是 **主板（`cn_main`）** 的口径。创业板（`cn_gem`）
> 与科创板（`cn_star`）波动天然更大，B2 箱体振幅、C1 突破缓冲、C3 追高上限都放宽：

| 参数 | 主板 | 创业板 / 科创板 | 说明 |
|---|---|---|---|
| `b2_T`（B2 箱体振幅） | 12% | **24%** | 创业板±20%涨跌幅，横盘区间本就宽 |
| `box_range`（B1 窗口振幅） | 15% | **30%** | 同上 |
| `daily_amp`（单日振幅） | 3% | **6%** | |
| `c1_buffer`（C1 突破缓冲） | 0.5% | **1%** | |
| `c3`（C3 追高上限） | 7% | **14%** | |
| `b3_T`（B3 实体幅度） | 2.5% | **5%** | |

其余因子的阈值三市一致。

### A 组：下跌确认（确认这是「跌下来的」）

| 编号 | 因子 | 定义 | 阈值 | 权重 |
|---|---|---|---|---|
| A1 | `drawdown` | 从近 250 日最高价回撤幅度 | ≥ 20% | 15 |
| A2 | `below_ma` | 收盘价到 MA60 的距离 | `\|close−MA60\|/MA60 ≤ 8%`（满分 ≤4%） | 7 |
| A3 | `ma_trend` | MA60 的近 20 日斜率 | ≤ 0 | 8 |

**A 组三项是入池必要条件**，不只是打分项。只用打分时，「跌深」这一腿几乎不筛人（回撤中位数远高于阈值），池子会被 Top-N 上限截断，与三段式原意不符。

**为什么用近 250 日高点**：横盘窗口最长可达 40 日。若回撤只看 60 日，一只横了 30 天的票，60 日内最高价很可能落在横盘区**内部**，回撤算出来接近 0，A1 失效。用一年高点作「跌下来」的真正起点；长窗口的风险（已涨回去的老票混进来）由两件事兜住：对 ≥60% 的回撤降权（基本面崩坏嫌疑），以及 B7 价格位置因子。

**A2/A3 为何放宽**：严格「均线空头排列」会把「已经横盘很久、均线刚开始走平」的票排除掉，而那恰恰是要抓的。

### B 组：横盘与「跌不动」（核心）

| 编号 | 因子 | 定义 | 阈值 | 权重 |
|---|---|---|---|---|
| B1 | `box_days` | 横盘持续天数 | ≥ 10 个交易日 | 硬条件 |
| B2 | `box_range` | 箱体振幅 = (最高 − 最低) / 最低 | ≤ 12%（主板）/ 24%（创业板、科创板） | 10 |
| B3 | `small_body` | 平均实体幅度 = mean(\|close−open\|/**前收**) | ≤ 2.5% | 7 |
| B4 | `vol_dry` | 量能枯竭 = 横盘期均量 / 下跌期均量 | ≤ 0.55 | **15**（硬下限 0.75） |
| B5 | `atr_squeeze` | ATR(14)/close 在近 250 日的分位 | ≤ 35 分位 | 10 |
| B6 | `ma_converge` | 均线粘合 = (max(MA5,10,20) − min(...)) / mean(...) | ≤ 6% | 7 |
| B7 | `price_position` | 现价在近 250 日区间的百分位 | ≤ 35% | 7 |
| B8 | `no_new_low` | 横盘期内未创前期新低 | 期间最低 > 下跌期最低 × 0.98 | 硬条件 |
| B9 | `three_flat` | 最近 3 根 K 线收盘价变异系数 | ≤ 1.2% | 4 |

**B1「横盘」的精确定义**（最容易含糊，必须写死）：最近 N 日窗口内同时满足

- `(max(high) − min(low)) / min(low) ≤ box_range_threshold`（整体振幅窄；**这是独立配置项，不是 B2 的 12%**）
- 每日 `(high − low) / close` 的中位数 ≤ `daily_amp_threshold`
- 窗口内收盘价 OLS 回归斜率绝对值 / mean(close) ≤ `slope_threshold`

B3 的分母用**前收**而非当日开盘，避免跳空把实体算大。

### C 组：突破确认（盘中触发，不是盘后）

| 编号 | 因子 | 定义 | 阈值 |
|---|---|---|---|
| C1 | `breakout` | 现价 > 箱体上沿 × (1 + buffer) | buffer = 0.5%（主板）/ 1%（创业板、科创板） |
| C2 | `volume_surge` | 盘中量 = 当前累计量 / **横盘期均量**（按时间进度折算） | ≥ 1.5 |
| C3 | `not_chasing` | 突破幅度标记（**不是否决条件**） | ≤ 上沿×1.07（主板）/ ×1.14（创业板、科创板） |

C2 的分母与 B4 同一口径（横盘期均量），按时间进度折算到当前时刻，否则开盘十分钟的量永远显得很小。

C3 只做标记不做否决：追高是用户自己的风险偏好，系统负责提示，不替用户拒绝。

## 3. 池子与触发

- **粗筛**用纯 SQL（`stock_meta` / `stock_stats`），门槛在 SQL 里先剔一遍，避免把全市场拉进 Python。
- **打分排序**取 Top N，分项因子值随池子落库。
- 池子告警 `pool_low` 为 **P1**、`pool_overflow` 为 **P2**（见 `notify/dispatcher.py::pool_alerts`）。
- **突破检测在盘中**：`event_log` 记录每次触发，去重与合并由 `notify/` 层处理。

池子规模是**波动量，不是常数**——市场急跌时箱体大面积破裂，池子会骤减；普涨时 B 组条件满足得多，池子会被 Top-N 截断。因此系统对「池子过小」发 P1 告警，而不是假设它总是稳定在某个区间。

---

## 4. 为什么不做的事

| 不做 | 原因 |
|---|---|
| 布尔筛选 | 满足条件的票数量剧烈波动，且无法排序取舍 |
| 盘后检测突破 | 突破是分时行为，盘后看收盘价已经错过买点 |
| 用复权价做盘中触发 | 盘中只有 raw 价；`adj` 仅用于历史形态比较 |
| 单一因子定生死 | 任何单因子都会被特定行情证伪，需要组合约束 |
| 自动下单 | 本项目只做提醒，不接交易接口 |
